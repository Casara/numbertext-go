# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
the versioning follows [Semantic Versioning](https://semver.org/). While the
project is on 0.x, a minor release may break the public API - see the API
stability section in the README.

## [0.1.0] - 2026-08-25

Initial release.

### Added

- A from-scratch Go interpreter for the Soros language
  (`internal/soros`), the regex-rewriting DSL
  [Numbertext.org](https://numbertext.github.io/)'s `.sor` rule files
  are written in: pattern/template compilation, `== prefix ==` macros,
  `$(...)`/`$N` recursive calls, `[...]` conditional text, `|`
  boundary modifiers, and the default NUMBERTEXT left-zero-deletion
  rule - built from the official Soros language specification and
  validated against its own canonical examples (string reversal,
  thousands separator, Devanagari digit conversion).
- The public API (`Cardinal`, `Ordinal`, `OrdinalNumber`, `Year`,
  `Currency`, `Money`, `Help`, the general `Convert` primitive, and
  `RegisterLocale` for adding a language at runtime from raw `.sor`
  text), all built on the embedded upstream rule files.
- All 52 `data/*.sor` locales from upstream
  [libnumbertext](https://github.com/Numbertext/libnumbertext),
  synced byte-for-byte (commit `a4b0225813b015a0f796754bc6718be20dd9943c`,
  `VERSION` 1.0.11 - see `data/SOURCE.md`), plus `scripts/sync-data.sh`
  to refresh them (which also reapplies the one local patch below).
- Regional variant support (e.g. `"en-GB"`, `"pt-BR"`): a code with no
  `.sor` file of its own falls back to its base language's file while
  still activating that region's `[:lang-code:]`-tagged lines.
- Build-tag-based selective embedding
  (`numbertext_select`/`numbertext_lang_<code>`): by default every
  bundled language is embedded, but a build can opt into embedding
  only a chosen subset to shrink the binary - see "Selecting which
  languages get embedded" in the README. `locale_<code>.go` files are
  generated by `scripts/gen-locale-embeds.py`.
- A hybrid regex engine (`internal/soros/regex.go`): Go's standard
  `regexp` (RE2) first, falling back to
  [`regexp2`](https://github.com/dlclark/regexp2) - a ported .NET/PCRE-
  style backtracking engine, timeout-bounded against catastrophic
  backtracking - only for the rare patterns RE2 refuses to compile at
  all (backreferences, lookaround). This is what makes `hu.sor`'s
  grammatical-suffix "database" lookup (`.*:\1:(-[^-:]*).*`) work
  correctly, including for genuinely ambiguous backreference patterns a
  simpler "single RE2 candidate + verify" approach would silently get
  wrong (raises the module's Go floor to 1.25, regexp2's minimum).
- Graceful degradation for any rule `Compile` genuinely can't parse:
  recorded in `Program.Skipped` rather than failing the whole locale.
  One real instance was found and fixed rather than left skipped - see
  the local patch below.
- One local patch to upstream data, pending a submitted fix: `bg.sor`
  had a bracket/paren transposed in an ordinal-thousands rule
  (`\2)])` instead of `\2))]`) - a plain typo, not a deliberate
  construct, confirmed by comparing against the correctly-nested
  singular rule right above it (see `data/SOURCE.md`'s "Local patches"
  section and AGENTS.md's "Resolved: bg.sor's one non-nesting rule was
  a data typo, not a parser gap" for the full reasoning, including the
  engine-side fixes considered and rejected first). `scripts/sync-data.sh`
  reapplies it automatically until upstream merges the real fix.
- A CLI (`cmd/numbertext`), doubling as a runnable usage example.
- `README.md`/`README.pt-BR.md`, `AGENTS.md` (`CLAUDE.md` imports it,
  `@AGENTS.md`, so Codex/Cursor/Claude Code all read the same
  instructions from one place), and this changelog.
- Quality tooling: `golangci-lint` v2 (`default: all`, tuned - see
  `.golangci.yml`), `go-arch-lint` enforcing that `internal/soros`
  stays a self-contained interpreter with no dependency on the rest of
  the module, `govulncheck`, `markdownlint-cli2`, `gremlins` mutation
  testing (`make test-mutation`/`test-mutation-dry-run`, not part of
  `make check` - it's a diagnostic to run periodically, not a merge
  gate), and `verify-docs` (compiles every runnable `package main`
  block embedded in the Markdown against the working tree, part of
  `make check`) plus `doc-sync` (a non-failing reminder of which docs a
  change to an exported symbol may have left stale) - all pinned and
  run through `make` (`make help` lists every target) and wired into
  CI (`.github/workflows/ci.yml`) except mutation testing and
  `doc-sync`, which stay manual/local.
- AI-assistant/editor scaffolding: `.claude/settings.json` (a scoped
  permission allowlist plus a `Stop` hook surfacing `doc-sync`),
  `.claude/agents/` (`api-surface-reviewer`, `bilingual-doc-reviewer` -
  read-only reviewers for the public API surface and the English/pt-BR
  doc pairs), `.vscode/` (editor settings and recommended extensions),
  `docs/coding-style.md`/`.pt-BR.md` (conventions beyond what the
  linters enforce), and
  [skills/using-numbertext-go/SKILL.md](skills/using-numbertext-go/SKILL.md)
  (a Claude Skill documenting the public API for projects that depend on
  this one, meant to be copied into them - see "Skill for AI assistants"
  in the README).
